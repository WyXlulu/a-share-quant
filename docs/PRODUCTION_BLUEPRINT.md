# 终态生产蓝图（Phase 4/5 设计输入）

> 本文档只描述 Phase 4/5 的目标工作流与架构边界，不包含任何实现。Phase 2/3 开发期间应把这里的边界当作约束，避免写出未来难以接入实盘的接口。

---

## 1. 终态工作流

### 1.1 T 日收盘后自动链

T 日收盘后，系统按固定顺序自动运行：

1. 数据增量更新。
2. 质检。
3. 信号生成。
4. 组合 diff。
5. 生成 `OrderIntent`。
6. 生成并锁定 `LockedOrder`。
7. 人工审批。

质检必须 fail-closed：若当日关键数据缺失、字段异常、PIT 可见性不成立或 taint 状态不允许出信号，则当日不产生可提交订单。

人工审批是系统唯一的每日人工环节：操作者在 dashboard 查看明日订单，选择一键确认或否决。确认后的 `LockedOrder` 才允许进入 T+1 broker adapter；否决则当日不提交订单。

### 1.2 T+1 开盘执行链

T+1 开盘时，已确认订单按固定顺序进入执行链：

1. 已确认 `LockedOrder` 经 miniQMT broker adapter 提交。
2. broker 成交回报转换为 `FillLedgerEntry`。
3. 实盘账本入账。
4. 与引擎影子账本逐笔对账。
5. 更新净值。
6. 触发告警检查。

告警至少覆盖：回撤超限、数据缺失、影子账本与实盘账本对账不平。告警必须主动通知，不能只写日志等待人工查看。

### 1.3 自动化定位

终态系统目标是 90%+ 自动化。人保留三件事：

1. 每日订单审批。
2. 总闸 kill switch。
3. 策略研究。

策略频率定位为日频：每日一次决策。盘中只做监控、对账、告警与 kill switch，不做盘中交易决策。

## 2. UI 五页面（Phase 4，Streamlit 起步）

### 2.1 今日概览

- 净值曲线。
- 当日 PnL。
- 当前持仓。
- 现金与应收。

### 2.2 明日订单审批

- 展示 `LockedOrder` 列表。
- 展示订单来源、目标数量、锁定数量、锁定价格上限、预留现金、拒单风险提示。
- 提供确认 / 否决操作。
- 审批结果必须可审计、可追溯。

### 2.3 对账页

- 展示影子账本 vs 实盘账本的逐笔差异。
- 展示成交价、成交量、费用、现金、持仓 lot 差异。
- 汇总滑点统计。
- 对账不平必须显著标红并触发告警。

### 2.4 数据健康

- 展示数据到齐率。
- 展示质检红旗。
- 展示 taint 状态。
- 展示缺数、异常值、PIT 可见性、公司行动处理状态。

### 2.5 告警与开关

- 展示回撤水位。
- 展示数据缺失、执行异常、对账不平、净值异常等告警。
- 提供 kill switch。
- kill switch 状态必须影响 broker adapter 提交路径。

## 3. 三条架构不变边界

Phase 2/3 开发期间必须守住以下边界。

### 3.1 `LockedOrder` 与 `FillLedgerEntry` 是回测与实盘的共同语言

实盘 broker adapter 只消费 `LockedOrder`，只生产 `FillLedgerEntry`。账本、公司行动处理、净值层对 adapter 替换无感。

策略层永远只产 `OrderIntent`，不得绕过锁定与执行边界直接调用 broker 或改账本。

### 3.2 信号函数 train-serve 一致

信号函数在回测与实盘中必须使用同一份代码，只更换数据源。不得为实盘另写一套语义不同的信号逻辑。

数据源替换必须经过 PIT 可见性、字段口径、时间戳和 taint 状态检查。

### 3.3 账本事件流不可变、可 diff

账本事件流必须保持不可变、可 diff，以支撑影子对账。任何更正都应追加纠错事件或形成可审计的重放结果，不得静默改写历史事件。

## 4. 已知延后项与 retrofit 接缝

### 4.1 增量数据更新

当前 build 仍是全量重拉。L1 已具备逐行 `available_at` / `snapshot_id` 结构，天然支持每日 append 模式。Phase 4/5 可新增增量构建器，不应改变 PITDataPortal 的外部语义。

### 4.2 账本状态持久化

当前 `PortfolioLedger` 是内存态。lot 与事件流均为纯 dataclass，后续可在外层增加序列化 / 恢复层。持久化层不得改变账本事件语义。

### 4.3 miniQMT adapter

miniQMT broker adapter 留到 Phase 5 实现。当前 `BROKER_ADAPTER_RULE` 已声明：实盘对接时必须逐字核对券商真实资金可用规则。adapter 接入时应沿用 `LockedOrder -> FillLedgerEntry` 边界，不得把券商 API 细节泄漏到策略、账本或净值层。
